Aula 11 — Comparações

Fazer perguntas sobre os dados

Um algoritmo frequentemente precisa responder perguntas como:

  • dois valores são iguais?
  • um valor é maior que outro?
  • um valor está abaixo de um limite?
  • um valor é diferente de outro?

Essas perguntas são feitas por meio de comparações.

Comparar não é calcular

Uma operação aritmética produz um valor numérico.

Uma comparação produz uma resposta lógica:

verdadeiro ou falso.

Por exemplo:

10 MAIOR QUE 5

A comparação é verdadeira.

Já:

3 MAIOR QUE 8

é falsa.

Comparações em Sophia

Sophia utiliza expressões como:

| Pergunta | Sophia | |---|---| | igual | IGUAL A | | diferente | DIFERENTE DE | | maior | MAIOR QUE | | maior ou igual | MAIOR OU IGUAL A | | menor | MENOR QUE | | menor ou igual | MENOR OU IGUAL A |

Igualdade

Para verificar se dois valores possuem o mesmo valor:

idade IGUAL A 18

Exemplo:

PROGRAMA "VerificaIdade"

INICIO
    NUMERO idade RECEBE 18

    SE idade IGUAL A 18
        ESCREVA "A idade e 18"
    FIM
FIM

Diferença

Para verificar se dois valores são diferentes:

senha DIFERENTE DE 1234

O objetivo é perguntar se os valores não são iguais.

Maior que

Para verificar se um valor ultrapassa outro:

nota MAIOR QUE 7

Exemplo:

PROGRAMA "NotaAlta"

INICIO
    NUMERO nota RECEBE 8

    SE nota MAIOR QUE 7
        ESCREVA "Nota alta"
    FIM
FIM

Maior ou igual

Essa comparação inclui o limite.

nota MAIOR OU IGUAL A 7

Se nota for 7, a condição é verdadeira.

Se nota for 8, também é verdadeira.

Se nota for 6, é falsa.

Menor que

Para verificar se um valor está abaixo de um limite:

idade MENOR QUE 18

Menor ou igual

Essa comparação inclui o limite:

idade MENOR OU IGUAL A 18

Se a idade for 18, a comparação continua sendo verdadeira.

Limites

Um dos erros mais comuns ao trabalhar com comparações é esquecer o limite.

Compare:

nota MAIOR QUE 6

com:

nota MAIOR OU IGUAL A 6

Na primeira:

  • 6 não atende;
  • 7 atende.

Na segunda:

  • 6 atende;
  • 7 atende.

Uma única palavra pode mudar o resultado do algoritmo.

Pensando como uma pergunta

Uma boa forma de construir uma comparação é transformar a regra do problema em uma pergunta.

Problema:

Uma pessoa pode entrar somente se tiver 18 anos ou mais.

Pergunta:

A idade é maior ou igual a 18?

Sophia:

idade MAIOR OU IGUAL A 18

Comparações em decisões

As comparações são frequentemente utilizadas dentro de SE.

PROGRAMA "Acesso"

INICIO
    NUMERO idade RECEBE 20

    SE idade MAIOR OU IGUAL A 18
        ESCREVA "Acesso permitido"
    SENAO
        ESCREVA "Acesso negado"
    FIM
FIM

A comparação determina qual caminho será executado.

Testando os limites

Quando existe uma comparação, devemos testar principalmente:

  • um valor abaixo do limite;
  • o próprio limite;
  • um valor acima do limite.

Para a regra:

idade MAIOR OU IGUAL A 18

os testes são:

| Idade | Resultado | |---:|---| | 17 | falso | | 18 | verdadeiro | | 19 | verdadeiro |

Esse tipo de teste ajuda a descobrir erros de lógica.

Erros comuns

Trocar MAIOR por MAIOR OU IGUAL

Isso altera o comportamento no limite.

Trocar MENOR por MENOR OU IGUAL

Novamente, o limite muda.

Comparar a variável errada

A condição precisa utilizar os dados que realmente determinam a regra.

Pensar somente em exemplos

Uma regra deve funcionar para todos os valores que pertencem ao problema, não apenas para um exemplo.

Atividade

Escreva a comparação Sophia correspondente a cada pergunta:

  1. idade é maior que 18?
  2. idade é maior ou igual a 18?
  3. nota é menor que 6?
  4. nota é menor ou igual a 6?
  5. senha é igual a 1234?
  6. número é diferente de 0?

Desafio

Uma escola considera um aluno aprovado quando sua nota é maior ou igual a 6.

Construa um programa que:

  1. receba a nota;
  2. faça a comparação correta;
  3. informe o resultado.

Teste com:

5
6
7

Observe especialmente o que acontece com a nota 6.

Síntese

Comparações transformam regras em perguntas que o algoritmo consegue avaliar.

Ao construir uma comparação:

  • identifique a regra;
  • transforme-a em uma pergunta;
  • escolha o operador correto;
  • observe os limites;
  • teste valores abaixo, no limite e acima.

Uma comparação aparentemente simples pode determinar todo o caminho de um algoritmo.
